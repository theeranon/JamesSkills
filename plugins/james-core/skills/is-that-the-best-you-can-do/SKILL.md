# Is That The Best You Can Do

Take it as a challenge: find every dimension where this could be stronger, then make it so.

## Scope

- Kind: workflow
- Owns: one delivered result that is correct but below what the situation deserves, raised beyond the recipient's expectation.
- Boundary: rewrites and extends the artifact under review. Preserves source facts: never invents benefits, numbers, approvers or commitments to look stronger. May widen into dimensions the brief did not name when they serve the same recipient and goal; must not change the goal itself or take an irreversible external action.

## Do not use this when

- The work contains actual defects, shortcuts, or residue -> `are-you-sure`
- The defects are in delivered code -> `dev-are-you-sure`
- The work is unfinished rather than unambitious -> `done-for-me`
- The result is fine but answers the wrong question -> `zoom-out`
- Several options must be compared and one recommended -> `give-me-solutions`

## Procedure

1. Read the invocation as "is this all you can do?" and answer it with work, not with a defence of the current version.
2. Name the recipient and the decision or use this result serves, then describe what would make them say it exceeded what they asked for.
3. Walk every dimension and mark where the result sits: depth of thinking, evidence and sources, efficiency for the reader or the system, structure and clarity, specificity, completeness against the real need, risks not yet considered, time and cost implications, and the dimensions the brief never mentioned but the recipient will judge.
4. Go and get what is missing. If the gap is evidence, research it with the rigour of `research-it`; if it is options, compare them with the rigour of `give-me-solutions`; if it is understanding, re-read the source and the project.
5. Rebuild from the strongest parts of the current draft. Keep what already earns its place; replace what does not.
6. Run the checks the format has and read the result once more as the recipient.
7. Return the improved work and, in a few lines, what was raised and what was deliberately left alone.

## Stop when

Every dimension in step 3 has been examined, each material gap is closed or named as needing an input only the user holds, and the result reads as more than was asked for. Do not stop at a self-set budget; stop when another pass would add nothing the recipient would notice.

## Principles

**Deliberate practice** — Improvement needs a target above current performance and honest comparison against it. Source: K. Anders Ericsson, The Role of Deliberate Practice, 1993
**Steelman before rebuilding** — State the strongest case for the existing draft before replacing it, so genuine quality is not discarded with the weakness. Source: principle of charity in argumentation; specific attribution uncertain
**Exceed the brief, not the goal** — Add what the recipient will value and never saw to ask for; never redefine what they are trying to achieve. Source: standing rule in this library
**Depth is not decoration** — Longer sentences, denser formatting and larger vocabulary are not improvement; only added substance, evidence or clarity counts. Source: standing rule in this library

## Counter-case

- The user says the deck is not good enough, and inspection shows the numbers do not reconcile. That is a defect, not a low ceiling, so `are-you-sure` owns it.
- The user asks for the best available tool for a job. Nothing here needs raising; `give-me-solutions` owns the comparison.
- The strongest improvement would be to publish the result somewhere new. Prepare it, but publishing stays a user-held gate.

## Hand back

The improved work in the requested format, followed by a short account of what was raised, what was left alone, and any input only the user can supply.

## Sources
