# Final It

Deliver the work, not production commentary about the work.

1. Choose the simplest format that serves the real recipient and use. Plain Markdown is correct when visual design adds no value. An HTML request stays HTML-only unless James asks for PDF or an authoritative recipient constraint requiring one fixed print file is directly confirmed; never infer that constraint from presentation language such as `A4`, `final`, or `client-facing`.
2. Transform instructions, complaints, drafts, and discussion into final wording. Remove AI theatre, design rationale, progress notes, copied requirements, and meta-copy.
3. Preserve source truth while changing presentation. Never invent or silently resolve a fact, quote, number, owner, deadline, promise, approval, or conflict. Keep unresolved material explicitly unresolved or return it as the one remaining content gate.
4. Apply the installed `make-it-james` shared standard (for tone) and `make-it-james-ux` (for UI/visuals) to every recipient-facing result. Do not force visual treatment onto a nonvisual artifact.
5. Complete native format checks and inspect every rendered page, slide, viewport, or state when rendering exists.
6. Deliver the usable artifact, its verification evidence, and only the recipient-relevant uncertainty that remains.

The result must read as if it was intentionally authored for its recipient, not exported from a conversation.
