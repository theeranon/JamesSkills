# Never Again

Treat the rejected example as evidence, not as the full scope of the defect.

1. Reconstruct the path from source and ingestion through identity, interpretation, state, policy, delivery, and recipient experience.
2. Locate the boundary that allowed the failure class, not merely the final bad phrase or record.
3. Generalize only as far as the evidence supports. Choose the narrowest durable scope: one output, one project, one workflow, or the shared library.
4. Correct the highest-authority reusable rule or mechanism at that scope.
5. Add three regression shapes: the rejected case, a different case with the same mechanism, and a legitimate counter-case the correction must still allow.
6. Audit active outputs affected by the rule and repair them in scope.

If the correction suggests a new skill, prepare a Candidate Card instead of creating or promoting it. Approval to repair the failure is not approval of a new name, ontology, or global package.

Do not accumulate one-case keyword bans when the failure came from judgment, ownership, evidence, or architecture.
